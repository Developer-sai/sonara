 # Build SONARA — Your Music. Your Aura.

 Create a polished, production-quality web application called SONARA.

 Tagline:\
 Your music. Your aura.

 ## 1\. Product Vision

 SONARA is a creative music-visualisation platform that turns a user's music listening, playlists, songs, albums and artists into beautiful personalised visual experiences.

 The core idea is:

 > What if your music could become an image?

 Users should be able to provide music through supported integrations or links, select a timeframe or collection, and generate a personalised Music Cloud — a visual composition containing song titles, artist names, album artwork/thumbnails, colours and listening information.

 SONARA should feel like a combination of:

 - Music discovery
- Personal music identity
- Digital collage creation
- Canva-style visual design
- Spotify/YouTube Music sharing aesthetics
- Social-media-ready content
- Personal visualisation

 SONARA is not a music streaming service.

 It is a creative layer that works around a user's existing music ecosystem.

 Add your music → Choose what to visualise → Generate → Customise → Share

 # 3\. MVP Input Methods

 Create an input screen called:

 ## "Add your music"

 Give users several options.

 ### Option A — Paste a music link

 Allow users to paste supported links such as:

 - Spotify song links
- Spotify album links
- Spotify playlist links
- YouTube Music links
- YouTube playlist links
- Other supported music URLs

 Example:

 Button:

 > Add music

 The application should identify the provider and parse the link.

 Do not scrape websites, bypass authentication, or circumvent provider restrictions.

 Use official APIs or permitted metadata sources wherever available.

 If an integration cannot legally or technically provide the required information, gracefully explain the limitation and allow the user to manually add songs.

 # 4\. Spotify Integration

 Build the application with a provider abstraction so Spotify is one provider rather than the entire application's architecture.

 Create:

```
MusicProvider
├── SpotifyProvider
├── YouTubeMusicProvider
├── ManualProvider
└── Future providers
```

 Spotify should use official OAuth/API functionality where available.

 Never expose client secrets in the browser.

 Use a secure backend/server-side integration where required.

 Only request the minimum permissions necessary.

 Provide:

 > Connect Spotify

 After connection, users should be able to select available music/listening data that the authorized API permits.

 Do not assume that every desired listening metric is available.

 Do not create unsupported derived Spotify metrics.

 Do not download Spotify content.

 Do not modify, crop, alter or permanently redistribute provider artwork.

 Where provider content is displayed, preserve required attribution and links back to the relevant provider content.

 Build the system so provider-specific restrictions can be enforced independently.

 # 8\. Cloud Algorithm

 Build a deterministic but visually varied layout engine.

 Inputs:

```
songs[]
artists[]
albums[]
frequency[]
ranking[]
artwork[]
theme
density
canvasRatio
```

 The algorithm should:

 1. Identify repeated artists.
2. Identify repeated songs.
3. Calculate relative importance where permitted.
4. Assign visual weights.
5. Place high-priority elements prominently.
6. Avoid overlapping important text.
7. Cluster related elements.
8. Create visual balance.
9. Generate background colours.
10. Produce a visually interesting composition.

 The result should feel like a designed poster rather than a spreadsheet.

 Example:

```
                 ARTIST A

       SONG TITLE             ARTIST B

   [album]       SONG C

                 ARTIST C

      [album]                 SONG D

             ARTIST A
```

 Allow the cloud to contain hundreds of elements while maintaining readability.

 # 35\. Important Provider Compliance

 Treat every third-party music service as an independent integration with its own legal and technical rules.

 Do not:

 - Scrape private user data
- Bypass authentication
- Circumvent API restrictions
- Download protected audio
- Rehost provider artwork without permission
- Modify provider artwork where prohibited
- Pretend SONARA is affiliated with Spotify or YouTube
- Claim unsupported listening statistics
- Create fake streaming statistics
- Use provider content to train AI
- Replicate the core functionality of a music-streaming service

 Spotify's current policy explicitly prohibits several of these uses and says applications must add independent value rather than replicate/replace a core Spotify experience.  Spotify for Developers

 Build SONARA as a creative visualisation product, not a replacement music player.
